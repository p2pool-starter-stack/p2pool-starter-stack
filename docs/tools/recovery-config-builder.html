Pithead recovery configuration builder

Writes a pithead-config.json for the USB stick, offline, in this page. Nothing is uploaded and nothing leaves this browser — save the file and copy it to the stick.

How the machine reads this file. The stick’s file is merged over the machine’s running configuration: it changes only the settings it names, and everything else keeps its current value. So tick only the settings you actually want to change. The machine validates the result at boot, prints every change on its console, and applies it after a 60-second countdown — pull the stick during the countdown to cancel.

The file holds a password and your payout addresses in plain text. Delete it from the stick once the machine has applied it.

What this page checks, and what it does not

Addresses are checked here the same way the machine checks them: the character set, the length, and the checksum every Monero and Tari address carries — so a single mistyped character is caught at this laptop instead of at the machine. The password is checked for length and for characters the machine refuses.

The machine is still the authority. It re-checks everything at boot and refuses a file it does not accept, printing the reason on its console. This page never blocks the download: if a check here disagrees with you, you can still save the file and let the machine decide.

A box you leave blank is left out of the file altogether, so it can never clear the setting on the machine — an empty password would otherwise merge in as “no password” and take the dashboard login away. It also means the machine says nothing about a blank box: that setting is not in the file to object to.

It cannot check what it cannot see — whether a wallet is yours, or what the machine’s current settings are. Read the change list the console prints before the countdown runs out.
